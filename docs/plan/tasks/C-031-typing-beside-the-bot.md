## Goal

`03-engine.md` section 6: typing in a tile must not break the bot. Today any typed line goes
straight to the game and pauses the bot. After this card, with a bot running, a line the game
would read as talk or look (`gossip hi`, `st`, `look`, `who`) goes out at the bot's next prompt
boundary without pausing it, an acting line (`n`, `a rat`, `rest`, `buy`) pauses the bot and
then goes, an attack while engaged is held with a warning (the player can force it), and raw
keys always go straight through and pause. The game's own command table decides which is
which.

## Behaviour

- **Gateway.** With a brain attached and the session's bot `running` or `paused`, an
  `input_line` from a UI is not sent to the game: it goes to the brain as `user_input
  {session, text, from}` and the gateway answers nothing more. With no brain, or the bot
  `stopped`, lines go straight through as today. `input_keys` always go straight through, and
  the gateway tells the brain with `keys_sent {session}` so it pauses. The brain tells the
  gateway which sessions it arbitrates with `arbitrate {session, on}` (sent on start/stop),
  so the gateway never holds input for a session the brain is not playing; if the brain
  disconnects, every session falls back to straight through at once.
- **Classification** (`commands.rs`): the first word through the prefix table from the
  fixture (a `CommandWord` run table built at load, tested against every fixture entry), then
  a kind by `CMD_` code: *talk and look* (SAY, GOSSIP, BROADCAST, TELEPATH, YELL, AUCTION,
  WHISPER, LOOK, STATUS, EXPERIENCE, INVENTORY, HEALTH, WHO/SCAN, TIME, HELP, SET, the
  punctuation forms `'`, `-`, `>`, `/`), *acts* (every movement word, ATTACK, BASH, CAST,
  REST, GET, DROP, BUY, SELL, WEAR, WIELD, OPEN, SEARCH, ...), *forbidden while engaged*
  (ATTACK, BASH, BACKSTAB, KILLBLOW, PUNCH and their synonyms), *unknown* (no command: a text
  exit phrase or speech: treated as an act, since `borrow skiff` moves). The table of kinds
  lives in one place with a test per quirk the KB lists.
- **Brain.** A *talk and look* line is queued and sent at the next prompt when nothing is in
  flight, the bot unpaused; its output is not used for confirmations (the executor ignores
  a `RoomSeen` that a player's `look` produced? No: a look's room is still the room; only
  action confirmations are gated on the action's own command). An *act* pauses after the
  action in flight ("You took over Kasimir"), then goes. A *forbidden while engaged* line is
  held: `input_held {session, text, reason}` to the UIs; the UI shows it on the tile with a
  `send anyway` button, which sends `user_input` again with `force: true`. Raw keys: pause.
- **UI**: the held line and its button in the tile footer; `docs/web-ui.md`.

## Design notes

- The gateway's part is routing by a flag per session (`arbitrate`), nothing more; the
  brain decides. `user_input` keeps the text; `sent` still reports what finally went out.
- `commands.rs` is pure and fast (a prefix run table, as silvermere's); the fixture test
  feeds every entry and checks the code; a second test checks every kind assignment the KB
  names.
- The queued "after this fight" line from the plan is this card's queue with one entry.
