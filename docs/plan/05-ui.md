# 05. The UI

One web UI (browser and desktop), one terminal UI. Both render the same two streams from the
core: the raw terminal output and the brain's state and events (`02-architecture.md`).

## Look

- **Old-school by default.** The IBM VGA fonts from the Ultimate Oldschool PC Font Pack
  (int10h.org, `Px437 IBM VGA 8x16` and its 9x16 and 8x14 cousins) with true CP437 glyphs; the
  16 DOS colours at their VGA values; panels drawn with CP437 box characters and shading
  blocks. An optional CRT effect (scanlines, slight glow) in the web UI.
- **Modern where it helps.** A clean monospace font option for dense layouts; light and dark
  chrome themes around the classic game pane; scalable everything.

## Views

| View | Shows | For |
|---|---|---|
| **Tile** | 1 to 6 full terminals, laid out by count and screen shape (1, 1x2 side by side, 2x2, 2x3 or 3x2) | Watching a whole party at once |
| **Focus** | One large terminal, a strip of status cards for the others | Playing one character while the others run |
| **Party** | The leader's terminal, member cards, the party map and a merged party log | Group play |
| **Cards** | Status cards only | A phone, or a corner of a second screen |

Layouts can be saved and switched with a key. Any card can be clicked to focus that
character.

**A tile** has a header (name, level and class, HP and mana bars, the current mode and its
narration line, a paused badge) above the terminal. **A status card** has the same header plus
exp/hr and alerts: low HP flashes, dead, disconnected, paused, a tell waiting.

**Every tile and card carries that character's bot controls**, always visible:

```
╔═ Kasimir  L5 Witchunter ══ HP ████████░░ 41/52  MA ██████████ 20/20 ══ [▶ Start] [⏸] [⚙] ═╗
║ Resting to 80%: Arena spawns, walked to the Hallway first                                  ║
```

- **Start/stop** turns that character's bot on or off (stopped = manual: the client is a plain
  terminal for it, with status still live).
- **Pause** holds it for a moment (guard reflexes stay on, `03-engine.md` section 5).
- **⚙** opens that character's bot settings at the essentials page, as a drawer beside the
  tile, so a threshold can be changed while watching the effect.
- **Where next?** sits in the same menu: the area recommendations for that character, with
  "go there" and "set as this character's area" buttons.

**Side panels** (toggle per view): the map (world data plus the position belief; click a room
to walk there), the room (exits, items, monsters, all clickable), the bot (mode stack,
narration history, the plan and loop position, pause and manual buttons), statistics (exp/hr
over time, kills, deaths, flees per area), settings (`04-settings.md`).

## Fonts and scaling

- Each terminal keeps the game's **80 columns**: the server formats for 80, so tiles scale the
  font to fit rather than reflowing. "Fit to tile" is the default; zoom per tile with
  `Ctrl +/-`, and a global size in settings.
- The pixel fonts are crisp at native sizes and whole multiples; six tiles on a 1440p screen
  land around 10 to 12 px, where the modern font reads better. The font is a setting per view.
- xterm.js renders with WebGL; browsers allow about 16 WebGL contexts per page, so six tiles
  fit easily (the canvas renderer is the fallback).

## Scrollback and logs

- Each terminal keeps a fast recent buffer (default 10,000 lines, a setting). Scrolling past
  it loads older output from the gateway's log; the full history is on disk.
- **Scroll without losing the live view**: scrolling up splits the pane, with the history above
  and the live bottom lines below, until you scroll back down.
- **Search** (`Ctrl+F`) in one character or all; **filters** for combat, loot, chat and the
  bot's narration.
- **Merged log**: one timeline of every character's events, colour-tagged by character.

## Input

- Keys go to the focused terminal. Each character has its own command history.
- A **command bar** takes prefixes: `2:rest`, `kas:rest` (name prefix), `party:rest`,
  `all:rest`. A broadcast toggle sends everything typed to all characters.
- Typing never breaks the bot: talk and look commands go out between its actions; acting
  commands pause that character first (`03-engine.md`, section 6).
- Keypad movement by default (MegaMud's macros mapped the keypad to directions); macros and
  hotkeys are a settings page.

## Pause and control

| Key (default) | Does |
|---|---|
| `F9` | Pause or resume the focused character |
| `Shift+F9` | Pause or resume all characters |
| `F10` | Start or stop the focused character's bot |
| `Alt+1` to `Alt+6` | Focus a character |
| `Alt+T`, `Alt+F`, `Alt+P` | Tile, focus, party view |

Every key is rebindable, and every action also has a button. Pause-all must be reachable with
one key from every view and from the terminal UI.

## Notifications

Desktop notifications and sounds (each a setting) for death, HP below a threshold, a tell or
page, a disconnect, a level up, and the bot stopping because it is stuck.

## The terminal UI

`wayfarer tui` connects to a running core (local or over SSH) and offers the same views with
ratatui: each game pane is a VT emulator (`vt100` crate), panels are box-drawn, keys are the
same. Font and size are the terminal's own. It is built after the web UI, against the same
protocol, and is the natural way to watch a bot on a headless server.

## What gets built first

The UI grows with the engine (`09-milestones.md`): one live terminal tile in the browser
first, then the status header from parser events, then the bot panel with narration and pause,
then the settings page, then several sessions and the views, then the terminal UI.
